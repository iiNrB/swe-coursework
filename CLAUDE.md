# Software Engineering Coursework — Working Instructions for Claude

This repository holds my coursework for a 4-year B.Sc. in Software
Engineering at Islamic University of Technology (IUT), OIC, Gazipur. I
work on it from more than one machine, kept in sync through this private
GitHub repo. Read this file at the start of every session and follow it
without being reminded.

## Standing rules

1. At the start of every session, run `git pull` first, before doing
   anything else, so you are always working from the latest version no
   matter which machine I'm on.

2. Whenever you create or modify any file (notes, code, an assignment, a
   report — anything) and I have not said otherwise, finish the task by
   staging it, committing with a short clear message describing what
   changed, and pushing to GitHub. Then tell me in one short line that
   it's pushed. Treat "create/update this" as already including "and
   save it to GitHub" — don't wait for me to separately say commit or
   push each time.

3. If a push fails (no internet, merge conflict, not logged in, etc.),
   stop and tell me clearly what went wrong and what I need to do. Never
   say it succeeded if it didn't.

4. Never use --dangerously-skip-permissions / bypass-permissions mode.
   Ask before anything destructive — deleting a file, overwriting
   something without a backup, force-pushing, rewriting history.

5. Keep things organized by semester and course as the folder structure
   grows (e.g. semester-1/course-name/...). Don't move or restructure
   existing folders without asking me first.

6. If I haven't told you exactly what to create, ask first — don't
   invent file names, content, or folder structure on your own.

7. Before I say I'm about to close the session or shut down, do one last
   check that everything is committed and pushed, and tell me clearly if
   anything is still pending.
